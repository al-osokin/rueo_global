## Рекомендации по маршрутизации

### Механически (без LM)
- Чистое разбиение по `;` вне скобок + trim пунктуации.
- Раскрытие `~` в headword/основу по текущим правилам parser_v4.
- Вынос `_см._/_ср._` в `note/reference`, не в translation item.
- Нумерованные маркеры `1.`/`2.` хранить как boundaries, не текст перевода.

### Через Gemma
- Фрагменты с `(_или_)` и 2+ конкурентными eo-вариантами.
- Комбинированные списки `,` + `;` + скобки в одной строке.
- Смешанные POS/роли (действие + сущность) в одном RU-фрагменте.
- Параллельные RU/EO перечни, где нужен align по смыслу, а не по позиции.

### Только вручную
- Идиомы/разговорные формулы с прагматикой (`а ну`, `бог в помощь`).
- Редкие/сомнительные метки (`_сомнит._`, устар./диал.) при конфликте кандидатов.
- Сильно обрезанные/многострочные фрагменты с потерей контекста.

## Как быстро пройти shortlist в `/admin/review-v4`
1. Открыть `/admin/review-v4` и перейти по `art_id` из shortlist.
2. Для каждого блока сравнить candidate split с ожидаемой парой `eo|ru` из списка выше.
3. Если расходится только пунктуация/тильда — `Edit` и сохранить.
4. Если расходится смысл группировки (`или`, mixed list) — `Reject` и оставить note с паттерном.
5. После 10 кейсов сверить долю Accept/Edit/Reject и обновить правила L0.
